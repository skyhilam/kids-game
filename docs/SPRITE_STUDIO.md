# Canvas 素材工房

從遊戲首頁下方的「素材工房」進入，或開啟 `/kids-game/#sprite-studio`。本機開發網址：`http://127.0.0.1:5173/kids-game/#sprite-studio`。

## 使用流程

1. 選擇野餐、刷牙、送貨或單字貼紙，再選關卡和單個素材。
2. 修改構圖、原畫裝飾與局部配色，或使用組合種子生成。鎖定的部件不會被隨機替換。相同種子及鎖定部件得到相同結果。
3. 查看大圖及 64／32 px 小圖，可切換預覽底色。PNG 永遠保留透明背景。
4. 在「一鍵生成角色動作」選揮手、走路、跑步、跳躍、歡呼、開車或自訂描述，選 4／8／12 張姿勢後按生成。原圖是角色與畫風參考；生成服務回傳新姿勢，Canvas 只負責編排和播放。小車已有的 8 張開車原畫可直接使用。FPS（2–24）和每列格數（1／2／4／8）可隨時修改，不會重新生成。
5. 下載 Sprite 素材包，內有透明圖集 PNG、影格 JSON、可重新編輯的設計 JSON 與說明。也能分別下載 PNG／JSON，或保留原本的單張 64、128、256、512 px PNG。
6. 檢查滿意後按「標記完成」，再按「下一個未完成」。同一「遊戲／關卡／素材」只保留一個完成版本；動畫設定也會保存，修改後可更新這個版本，不會新增重複紀錄。生成服務另以參考圖、動作描述、影格數及種子識別工作，重複提交直接返回已有結果。

已使用 Chrome 實際下載 PNG 與 JSON，確認 PNG 尺寸、alpha 通道與設計參數。Codex 內嵌預覽沒有回報檔案下載；若未收到檔案，請用 Chrome 開啟同一網址下載。

完成紀錄存於目前瀏覽器的 `localStorage`（`picnic-sprite-studio-v1`）。切換素材時，本頁會保留未完成草稿；重新整理只恢復已標記完成的作品。清除瀏覽器資料會移除紀錄，重要作品請另存 JSON。無法存取儲存空間時，頁面會顯示提示。

「套用這個素材」會讓同一瀏覽器中所有遊戲的同名 `GameSprite` 使用目前造型。有內建或已生成的動作影格時，遊戲會依設定 FPS 循環播放整組姿勢；沒有相符影格時顯示單張造型。重新整理後會恢復動畫，舊有套用紀錄也會自動載入可用影格。若影格已被清除，工房會提示載入備份設計 JSON 並暫用靜態造型。按「恢復原有插畫」會停止動畫並還原原畫。這是瀏覽器內的預覽設定，不會將作品提交到原始碼或同步給其他玩家。

「小車」用於封面及說明；野餐棋盤上的車輛使用「小車・俯視」，兩者須分別套用各自的動作。

## 涵蓋範圍

工房提供四個遊戲主題的 **22 種**原畫合成素材，含側面／俯視車輛、人物、蛀牙蟲、牙齒、牙刷、食物、建築、植物、野餐場景與包裹。既有 246 個插畫 sprite 繼續保留；新拓展的 14 組主題圖集不是這次 Canvas 模型的範圍。聽詞揀圖共用單字素材，亦會使用同名素材的套用設定。

野餐和刷牙使用現行關卡生成器及難度分層；送貨以素材組編號對應示例路線種子；單字貼紙涵蓋目前 16 個單字素材，關卡資訊依難度顯示 4／5／6 張配對。關卡編號用來整理版本，各關原本共用相同素材。套用設定按素材名稱生效，不會改變迷宮、遊戲規則或針對某一關自動換圖。

工房在 Canvas 2D 中合成遊戲現有原畫，預設「遊戲原色／原作構圖／保留原作」會保留原圖比例、表情、陰影與水粉筆觸。調色依素材的顏色及區域遮罩作用於車身、衣服、屋頂等部分，保留明暗變化與透明通道；花朵及陽光裝飾也來自同一套圖集。原畫合成在瀏覽器內完成。生成角色動作時，會把目前原畫合成的透明 PNG 及動作描述送往 OpenAI；頁面輸入的 API token 只用於該次生成請求，不會寫入工作紀錄。

新版設計 JSON 使用版本 4，保存動作描述及生成工作識別。版本 2／3 保留單張原畫外觀及完成紀錄；版本 3 的整圖移動、旋轉、縮放、靜態模式已移除，改為待生成角色動作（小車可使用已有開車原畫）。版本 1 的幾何造型、表情與像素化設定會轉為原作插畫，保留素材、種子、尺寸、縮放、翻轉、關卡與完成紀錄；頁面會提示這項變更。現在的調整項目是構圖傾角、原畫裝飾、材質配色與輸出尺寸。

## 圖集格式

- ZIP 包含 `sprite.png`、`sprite.json`、`design.json`、`README.txt`。重新載入工房時選 `design.json`。
- 影格 JSON 採用 [Aseprite JSON hash](https://www.aseprite.org/docs/cli/#data) 的 `frames`、`meta.size`、`meta.image`、`meta.frameTags` 結構，額外提供中心 `pivot` 與 FPS。
- 所有格子保持相同尺寸，從左到右、從上到下排列；不裁掉透明邊距。未使用格子保持透明，預覽格線和編號不會匯出。
- `frame.duration` 以毫秒記錄，使用累積時間四捨五入來分配每格長度，避免非整除 FPS 的時間漂移。播放器可使用各格時間，或依 `meta.fps` 設定等速循環。
- 小車 `drive` 動作使用內建 imagegen 參考遊戲小車繪製的 8 張姿勢原畫，包含揮手、眨眼及輪轂角度變化。Canvas 依車身定位對齊各格，保留局部調色、構圖、翻轉及裝飾；角色動作固定 8 格，不複製靜態影格來湊數。
- 所有動畫均使用獨立姿勢影格，`meta.animationType` 為 `painted-poses`。沒有影格時顯示待生成，播放與匯出停用。舊整圖動畫程式已刪除。
- OpenAI 生成整張透明圖集後，程式使用整組共同比例整理成每格 256 px，保留手繪筆觸；跳躍、跑步及自訂動作保持全組共同座標，保留離地高度。64／128／256／512 px 是匯出尺寸，512 px 不代表原生解析度。每格直接繪製獨立姿勢，不另加整圖動效。更改原畫配色、姿勢描述等會使既有生成參考失效，須生成相符動作。
- 網上版生成影格保存在目前瀏覽器的 IndexedDB；本機開發版另外保存於 `.sprite-studio/jobs/`。下載設計 JSON 或 ZIP 時會內嵌影格，匯入後可離線播放及重新編排。網上版清除瀏覽器資料會移除影格；重要作品請下載備份。本機開發版的工作檔則不受影響。
- 小車動作的處理狀態、SHA-256、框位與驗證結果記於 [manifest](../src/assets/picnic/car-drive/manifest.json)；完整 [提示詞及來源](../src/assets/picnic/car-drive/README.md) 同目錄保存。一次只處理一個素材，已處理的小車不重複生成。
- 目前沒有四／八方向新視角或骨架編輯器；走路等動作由文字及原畫參考生成。

## 網上版一鍵生成

[正式工房](https://game1.iclover.net/kids-game/#sprite-studio) 是靜態網站。正式建置直接由瀏覽器呼叫 OpenAI Images API，不再要求只有 `npm run dev` 才提供的 `/__sprite-studio/status`。

1. 選素材、動作及影格數；自訂動作須填寫描述。
2. 貼上自己的 OpenAI API token。顯示「網上生成已就緒」後，按「一鍵生成角色動作」。API 帳戶須具備目前圖像模型的存取權及額度。
3. 生成時保持頁面開啟。token 只放在送往 `https://api.openai.com/v1/images/edits` 的 Authorization header，不經本網站伺服器、不儲存，重新整理即清除。
4. 結果保存在此瀏覽器，檢查後下載素材包並標記完成。生成紀錄不包含 token。

同來源頁面用 Web Locks 共用逐張生成限制；相同輸入會重用已有工作。若頁面關閉或連線中斷，紀錄轉為「待確認」，不會自動重送。先核對 OpenAI 用量，確認可以重試後按「已核對用量，解除待確認工作」，再手動生成。解除工作本身不會呼叫 API，也不會取消先前可能仍在 OpenAI 處理的請求。明確的 token 無效或額度不足會顯示原因，可修正後重試。

瀏覽器需要 HTTPS、Web Locks、localStorage 及 IndexedDB；正式建置可用 `npm run preview` 在本機重現。頁面不會將 token 寫入這些儲存空間。範例素材及離線匯入功能保持可用。

## 啟用本機一鍵生成

1. 執行 `npm run dev`，以 `http://127.0.0.1:5173/kids-game/#sprite-studio` 開啟工房。在「OpenAI API token」密碼欄貼上自己的 token，毋須設定檔案。欄位只保留在目前頁面記憶體，可按「清除 token」移除；重新整理或離開工房後會清除。
2. `OPENAI_IMAGE_MODEL` 預設為 `gpt-image-2.5-sunburst`，也接受 `gpt-image-2.5-flare`、兩者的 `2026-09-08` 快照、`gpt-image-2` 與 `gpt-image-2-2026-04-21`。GPT Image 2 的透明輸出仍為預覽支援，若帳戶拒絕此參數，工房會顯示失敗，不會暗中改用其他模型。API 與模型能力依 [OpenAI 圖像編輯規格](https://developers.openai.com/api/reference/resources/images/methods/edit) 和 [Sunburst 模型文件](https://developers.openai.com/api/docs/models/gpt-image-2.5-sunburst) 實作。
3. 工房會顯示目前模型，貼上 token 後可提交生成。API 帳戶仍須具備模型存取權和足夠額度。維護者也可選擇在 `.env.local` 設定 `OPENAI_API_KEY` 作為欄位留空時的備用金鑰；頁面輸入優先且不會修改此設定。環境金鑰不可加 `VITE_` 前綴或提交到 Git，變更環境設定後須重新啟動開發伺服器。
4. 選素材和動作後按一次生成。服務直接呼叫 OpenAI `POST /v1/images/edits`，以 `images[].image_url` 傳送透明參考畫布（原畫放在第一格）及原畫 PNG，要求 `n: 1`、透明背景、PNG 格式及完整連續姿勢圖集。4 格使用 1024×1024（2×2），8 格使用 1536×768（4×2），12 格使用 1536×1152（4×3）。每個模型請求只產生一張整組圖集，不把 `n` 當作影格數。
5. 本機立即回傳工作編號，瀏覽器每 5 秒查看本機狀態；OpenAI 的同步 Images API 在本機背景工作中執行，最長等待 10 分鐘。完成後先驗證 PNG 格式及尺寸，再檢查各格透明背景、邊界和影格差異，按整組共同比例整理成 256 px 姿勢。整理狀態隨設計保存，重新匯入不會再次縮放。
6. 播放並逐格檢查角色身分、筆觸、肢體動作與循環接點，再匯出。提示詞要求保持原風格及獨立姿勢，但模型並非專門的動畫引擎；格子內容與循環品質仍需目視檢查。程式拒絕切格超界、空白、不透明或全部相同的影格。

本機接駁隨 Vite 開發伺服器啟動，只接受 loopback 與同來源請求。GitHub Pages 正式版使用上述瀏覽器直接生成流程；網站建置不包含金鑰或伺服器程式。執行時不會呼叫 PixelLab。

本機開發版的頁面 token 僅在提交生成時透過 `Authorization` header 送往同來源本機服務，再用於 OpenAI 請求；不會放進 URL、設計資料、localStorage、sessionStorage、IndexedDB、工作檔案或匯出包。服務不會把它保存為下一次請求的金鑰，查詢狀態及讀取已完成影格也不會附帶 token。清除欄位不會取消已送出的生成工作。

每次只容許一個工作。工作內容識別包含 pipeline 版本、模型、參考圖及畫布、動作、描述、影格數及組合種子，相同輸入直接重用結果。OpenAI Images API 不接收 seed 參數；組合種子只用於原畫合成與本機重複工作識別，不保證重新送往模型後得到相同畫面。

OpenAI Images API 沒有可在重啟後續查的供應商工作編號。若伺服器重啟、逾時、網絡失聯或遇到無法確認結果的服務錯誤，工作會標為 `uncertain`，保留鎖定及 `requestId`，不自動重新付費生成。維護者須先核對 OpenAI API 用量或以 request ID 查詢；只有確認可再次提交後，才清除 `.sprite-studio/jobs/active.json` 的 `id` 並將該工作改為 `failed`。已完成的圖集會保留，可在重啟後繼續讀取。

未輸入 token 且沒有備用金鑰時，生成按鈕停用；只有本機服務無法連接才顯示「尚未連接生成服務」。測試使用模擬 API 回應驗證請求、token 不會保存及工作狀態，另以既有原畫組成測試圖集驗證切格；這不代表已完成線上 AI 生成品質驗證。真正的生成效果須接上有效 OpenAI 帳戶後實測。

## 維護

- `src/studio/catalog.ts`：22 種模型與四個遊戲的素材清單。
- `src/studio/draw.ts`：同源圖集載入、框位裁切、Canvas 合成、透明安全邊距、縮放與翻轉；快取有數量上限，非同步繪製只保留最新請求。
- `src/studio/materials.ts`：各素材的調色區域與色相遮罩，保留原畫紋理、輪廓和角色膚色。
- `src/studio/recipe.ts`：穩定種子、鎖定邏輯、參數驗證、版本 4 JSON 與版本 1／2／3 遷移。
- `src/studio/animation.ts`、`sheet.ts`、`SpriteSheet.vue`：角色動作選擇、固定框位圖集、動畫預覽及匯出。
- `server/sprite-generation.ts`：本機 OpenAI Images API 接駁、持久工作紀錄、逐張處理、輪詢和重複工作重用。
- `src/studio/generation.ts`：依正式／開發建置選擇接駁方式、動作提示詞、影格驗證及 IndexedDB 保存。
- `src/studio/browserGeneration.ts`：正式站直接呼叫 OpenAI、跨頁面逐張限制及中斷後的待確認紀錄。
- `src/studio/imageProvider.ts`：網上版與本機版共用的請求格式、模型、圖集驗證及錯誤訊息。
- `src/studio/spritePipeline.ts`：原畫參考畫布、整組共同比例與定位；採用官方流程的方式見 [Sprite Pipeline 接駁](SPRITE_PIPELINE.md)。
- `src/studio/actionFrames.ts`：載入、對齊及調色已完成的小車動作原畫；限制快取數量。
- `src/studio/download.ts`：PNG 編碼、檔案下載與無額外依賴的 ZIP 打包。
- `src/studio/store.ts`：完成紀錄及可還原的瀏覽器套用設定。
- `src/studio/SpriteStudio.vue`：工房介面，首頁透過 hash 路由載入。

新增素材時，把已登錄圖集框位的名稱及用途加入 catalog，在 materials 指定主要材質的色相及區域，最後加入對應遊戲清單。沿用同源素材，避免跨來源畫布無法匯出的問題。未來調整配方語意時，須更新 `Recipe.version` 並提供版本處理。

## 驗證

`npm test` 包含素材覆蓋、種子、鎖定、JSON 往返、不合法輸入、舊版遷移、完成紀錄、圖集座標／時間與 ZIP 完整性驗證。`npm run build` 執行型別檢查與正式建置。

啟動 `npm run dev`，開啟 `/kids-game/tests/studio-browser.html` 可在真實 Canvas 上檢查 22 個模型、660 次繪製、四種輸出尺寸、透明邊界、三種構圖、翻轉、材質調色及 PNG alpha；預設輸出另外與原畫等比例繪製做逐像素比對，並檢查非同步繪製不會讓舊選擇蓋過新選擇。小車角色動作另驗證 32 組尺寸／排版／翻轉組合，以及手臂輪廓變化、閉眼變化、局部調色和 ZIP 產生。另用明確標示的原畫測試影格驗證生成结果解碼、拒絕全相同影格／不透明背景，以及可攜設計包含完整影格。這些固定測試素材不代表已完成線上 AI 生成品質驗證。頁面同時顯示完整素材檢視表。這個測試頁不會打包進正式網站。

正式建置的瀏覽器流程亦驗證輸入 token 後按鈕啟用、中斷後解除待確認工作及重新整理清空 token。HTTP 測試確認 OpenAI 接受跨來源預檢；無效測試 token 回傳 401，但該錯誤回應缺少 CORS 標頭，內嵌瀏覽器因此顯示未能確認結果。401／額度不足的可讀回應及成功生成流程另以模擬回應驗證；沒有使用用戶 token 做付費生成。

人工瀏覽器流程另外驗證：種子錯誤提示、鎖定部件、標記完成、重新載入、跳過已完成項目、遊戲套用與恢復，以及 390 px 手機版無水平溢出。

瀏覽器驗證亦會把本機測試影格套用至真正的 `PicnicBoard`，檢查循環播放、逐格裁切、寬形車輛視窗不滲出相鄰影格、SVG 非空白，以及恢復原畫後停止播放；測試結束會還原先前的套用紀錄。單元測試另涵蓋重新載入套用設定、影格缺失提示及非同步套用／恢復的競態。
